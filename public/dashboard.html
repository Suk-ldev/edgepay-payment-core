使用文档

下面的地址按当前站点生成，可直接复制。

ePay V1 接入

商户 ID 为 1000。兼容 /submit.php、/mapi.php 和 /api.php，签名方式保持 ePay V1 的 MD5 规则。密钥从上方“密钥管理”复制。

将原系统支付地址改为本站域名即可，订单号、异步通知、同步返回与查询参数不需要另写一套。

微信官方 V2 支付产品

插件保留一个 wechat_api，按支付环境选择产品，不需要更换 ePay V1 接口。先在微信商户平台开通产品，再在插件配置勾选相同产品并填写对应 AppID。

  • Native：device=pc，统一下单返回二维码。
  • H5：device=mobile、qq、alipay 或 jump，需配置已经登记的 H5 网站 URL。
  • JSAPI：device=wechat。可随订单传 openid；留空时需配置公众号 AppID 与 AppSecret，由收银台走 snsapi_base 自动授权。
  • 小程序：随订单传 mini_openid，/mapi.php 的 pay_info 可直接交给小程序 wx.requestPayment。
  • APP：device=app，/mapi.php 的 pay_info 返回微信 APP SDK 调起参数。
微信个人收款监听（SmsForwarder）
  1. 先在通道管理找到“微信个人收款监听”的通道 ID，并在插件配置填写 SmsForwarder 密钥和收款二维码。
  2. SmsForwarder 请求方式选 POST，Webhook 填写 /api/pay/{通道ID}/notify，Secret 与插件配置保持一致；成功关键字仍可填写 200。
  3. 自定义模板填写 {"title":"{{TITLE}}","msg":"{{MSG}}"}；监听应用包名为 com.tencent.mm。
  4. 通知标题允许“微信支付”“微信收款助手”“微信收款商业版”。测试时先生成待支付订单，再按收银台显示金额准确付款。
  5. 直接打开通知地址会返回 ready 探活结果；实际投送会返回 confirmed、duplicate 或 unmatched，并明确说明是否确认订单。
  6. 仅当旧客户端严格要求正文为 200/400 时，在通知地址后追加 ?legacy=1，成功关键字填写 200。
支付宝官方支付产品

alipay_api 对外仍使用 ePay V1。只勾选已经在支付宝开放平台签约并上线的产品。

  • 电脑网站：PC 环境调用 alipay.trade.page.pay。
  • 手机网站：移动环境调用 alipay.trade.wap.pay。
  • APP：/mapi.php 的 pay_info 返回原生支付宝 SDK 使用的 order string。
  • 小程序 JSAPI：需传 buyer_open_id 或 buyer_id；返回的 pay_info.tradeNO 交给 my.tradePay。
  • 订单码：调用 alipay.trade.precreate 并展示支付宝二维码。
  • 当面付：需传当前有效的 auth_code；提交后会真实发起扣款。

后台“通道管理 → 测试”可明确选择产品。自动模式只有在支付宝返回未签约或权限不足时才尝试后备产品，不会吞掉金额、签名或身份错误。

一个平台两个账号：复制插件

同一个收款平台要挂两个账号（例如一个微信收商业单、另一个收个人单）时，在“插件配置”里点这一行的复制，填一个认得出的名字并勾选“同时新建通道”。副本的编码形如 wxpay_receipt~2。

  • 配置各填各的。复制不会带走原账号的密钥和收款码——带过去只会让两条通道抢同一笔到账。副本建出来是停用的，补齐配置后再启用。
  • 订单、流水去重、轮询租约按副本分开。一个账号的到账通知不会被拿去匹配另一个账号的订单。
  • 分流看通道权重。两条通道同为一种支付方式时，权重 70 / 30 就是七三分；调成 0 等于只走另一个账号。
  • 不用再买一次。授权按平台算，副本跟着基础插件的 License 权益走。
  • 监听端按"配置编号"认领。副本那行的标签就是它的编号：默认配置是 0，第一份复制是配置 1，以此类推。Docker Watcher 会自动接管所有副本，不用为它单独开容器；应用宝桥接器则是一个微信一台，用 PLUGIN_INSTANCE 填编号，没被认领的配置不会有人去接管。

副本可以随时删除，它的配置和通道一并删掉，历史订单保留。基础插件删不掉，它是构建的一部分。

监听方式：哪些在 Worker，哪些需要 Docker

统一优先级：Docker Watcher 在线且声明支持对应插件时，由 Docker 查询；容器离线超过两分钟后，具备 Worker 查询能力的插件自动接管。

Worker 后备：付呗、收钱吧、支付宝账单、海科码钱、天阙 Pretran、旺铺管家、USDT，以及已填写 Token/Cookie 的拉卡拉直连、星驿付直连和小Y经营。

只由 Docker 查询：富友、拉卡拉普通版、星驿付普通版、天阙会生活、易宝老板管账、易生收款啦和盛付通。盛付通使用官方页面的动态 SM2/SM4/SM3 加密请求，不在 Worker 中复刻。

外部排查时可访问 正在读取触发地址… 手动跑一轮。返回值会列出待监听订单、发现流水、确认成功和错误明细；正常使用不要求另配这个计划任务。

不知道商户号、门店号、终端号或码牌 ID
  1. 先在“插件配置”保存平台登录账号和密码；直连插件也可保存 Token 或 Cookie。未知编号先留空，配置暂时不完整也可以保存。
  2. 纯 Docker 插件先确认 Watcher 在线。用目标码牌真实收一笔容易辨认的小额款，等第三方平台显示成功。
  3. 5 分钟内回到插件编辑区点“查询最近流水”。查询会忽略当前填写的编号筛选，展示平台实际返回的商户、门店、终端和码牌编号。
  4. 按时间、金额、支付方式和商户名称找到目标流水，点“填入编号”，核对后再保存插件配置。

查询最多展示近 5 分钟的 20 条成功流水，不会创建或确认 EdgePay 订单，也不返回付款人、备注、Cookie 或 Token。平台没有返回的编号会保持空白，不要用订单流水号代替。

Worker 主动查询：更快确认到账

收款确认有三种触发方式：① 收银台打开期间会按插件即时查询；② 部署向导里勾选了“启用每分钟后台轮询（Cron）”时，Worker 每分钟自动跑一轮；③ 用外部计划任务按固定间隔主动访问下面的触发地址（例如每 7 秒一次），Worker 收到后立即跑一轮。想比每分钟更快确认，或部署时没启用 Cron，就用第三种。

正在读取触发地址…

  • URL 已自带 POLL_TRIGGER_TOKEN，直接填进任意 HTTP 计划任务（如青龙、cron、Uptime 监控、云函数定时器）即可，不需要请求头、请求体或 Node。
  • 没有待支付订单时，这个接口不会请求任何收款平台或 TronGrid，空跑几乎没有成本；间隔越短确认越快，按需要设置即可。
  • 部署向导没勾选 Cron、也不主动访问时，只有收银台打开期间才会查询；纯监听类插件建议至少启用其一。
  • 该地址属于敏感凭据，不要放进公开日志或前端页面；泄露后到上方“密钥管理”轮换轮询 Token 即可。
商业版插件：配置顺序
  1. 先到 License 站确认域名已经购买对应插件。增购沿用原 License，不需要重新部署 License。
  2. 在“插件配置”找到插件，先保存账号、密钥或 Token/Cookie。商户号、门店号和终端号不知道时，按上面的“查询最近流水”流程识别并回填。
  3. 到“通道管理”新增通道。一个通道只选一种支付方式；同一插件要同时收微信和支付宝时，建两个通道。
  4. 标注为 Docker Watcher 的插件要保持容器在线。容器里的 WORKER_URL、EDGEPAY_LICENSE 和 TRANSPORT_KEY 必须与当前 Worker 对应。
  5. 从通道右侧点“测试”，先用小额订单确认收银台、流水匹配和商户回调都正常，再接生产订单。

平台密码、API 密钥、Cookie 和 Access Token 保存后只显示掩码。密码框留空会保留原值。二维码建议上传实际收款码，不要上传平台首页或登录码。

客服页

在“收银台设置”上传客服头像与二维码并启用后，公开地址为 /contact。页面会自动跟随系统的浅色或深色模式，不提供跳转按钮。

监听排查

如果没有确认订单，依次检查：订单是否仍在该通道设置的有效期内、付款金额是否完全一致、通道 ID 是否正确、签名密钥是否一致、Watcher 时间是否准确、通知响应是否为成功关键字。
